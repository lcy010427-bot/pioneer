## 구현 결과

위 목표를 구현했습니다. 핵심은 `pioneer/radar.py`, `web/radar.js`이며 기존 분석·자료 수집·명칭 조회 코드를 재사용합니다.
기본 화면은 Hot Radar, 기존 여섯 탭은 ‘물질 분석’으로 연결했습니다. 세부 분석은 진입 시 조회해 탐색 초기 로딩을 줄이고,
동일 제목·초록의 맥락 규칙 결과를 한도 10,000개 캐시합니다. 모바일은 후보별 카드로 표시합니다.

- 비교는 같은 검색 사전·같은 일수·같은 문서/맥락 필터. 현재 동의어와 일치하고 요청 기간을 덮는 완전 스냅샷을 우선 선택합니다.
- 더 좁은 최신 실행이 넓은 과거 완전 실행을 잘못 대체하지 않습니다. 현재 검색 사전이 바뀌면 과거의 다른 검색식으로 판정하지 않습니다.
- 기저 0건은 % N/A·초기 신호. 저빈도·미수집·부분 수집·상세 날짜 미상은 구별합니다. 미상 날짜가 있으면 선그래프를 0건으로 채우지 않습니다.
- 후보의 새 맥락 언급은 비교 가능한 범위에서만 제안합니다. 키워드·부정 문장의 언급을 실제 효과·측정·과학적 신규성으로 올리지 않습니다.
- 비교 후보 2~3개, 이유 코드·근거 논문 페이지·검색식·수집/규칙 버전·조건 민감도를 확인할 수 있습니다.
- 저장 분석은 불변이며 화면 이후 자료 변경 시 저장·근거 조회를 보류합니다. 판단 이력은 별도 append-only로 연결하고 CSV·JSON에 포함합니다.
- 환경 문헌 후보 발굴과 명칭 기반 조회 대상 편입은 사람이 검토한 식별/선정과 구별합니다. 자동으로 인간 검토 기록을 만들지 않습니다.
- 자료 갱신은 백그라운드 작업, 한도·진행률·부분 실패·캐시 재사용·이전 스냅샷 보존을 지원합니다.
- 기본 조회는 외부 호출·DB 쓰기 없이 작동합니다. 추가·수집·문헌 탐색은 사용자 버튼 요청으로만 시작합니다.
