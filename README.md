# PIONEER · 환경화학물질 Hot Radar

환경화학물질의 문헌 관심 증가 후보를 찾고, 시간 추이 → 선정 이유 → 근거 논문 → 후속 검토를 연결하는 한국어 웹 앱입니다.
**현재 공개 배포는 하지 않았으며, Docker 기반 배포 구성을 준비했습니다.** 과학적 판정·위해성 예측·전문가 검토 완료를 주장하지 않습니다.

## 배포 준비

**누구나 조회, 운영자만 갱신·기록**하는 HTTPS 배포 구성을 제공합니다.
공개 조회/운영자 도메인 분리, 운영자 로그인, 공개 API 쓰기·내부 기록 차단, 읽기 전용 공개 데이터 볼륨,
영구 SQLite·백업/복구·건강 상태 점검·재시작 복구·비특권 컨테이너를 포함합니다.
Docker 이미지는 데이터·실제 계정을 포함하지 않으며, 현재 실자료는 별도 이관본으로 옮깁니다.

- 실행 순서와 서버/DNS 조건: [배포 안내](docs/deployment.md)
- 터미널 없이 GitHub와 Render 화면으로 게시: [쉬운 배포 안내](docs/render.md)
- 검증 범위: [배포 검사 기록](docs/deployment-validation.md)
- 배포 패키지 재생성: `python3 scripts/package_deployment.py`
- 설정 생성: `python3 scripts/configure_deployment.py` (실제 `.env`는 Git/패키지/이미지 제외)
- GitHub Actions는 검사·이미지 빌드만 실행하며 공개 배포·이미지 push를 하지 않습니다.

## Hot Radar · 기본 화면

- 조회 목록에서 물질명·동의어·CID 검색, 증가량·증가율·후반 문헌 수 정렬, 기간·맥락 키워드·문서유형 필터.
- 5년 / 1년 / 최근 3개월 / 직접 기간. 동일 일수의 앞·뒤 절반을 비교하고 선그래프·원본 논문으로 연결.
- 문헌 관심 증가 / 0건 기저 초기 신호 / 저빈도 / 감소 / 조건 미충족 / 자료 부족을 구분합니다.
- 같은 조건으로 후보 2~3개 비교. 새로운 매질·endpoint·모델의 **언급**과 기준 민감도 확인.
- 물질별 이유·논문 20건씩 조회, 물질 분석 연결, 분석 조건·검색식·run·근거를 불변 스냅샷으로 저장.
- 해당 분석에 선정·보류·제외 판단과 기록자·이유를 추가. 저장 분석의 CSV·JSON에 판단 이력을 함께 내보냅니다.
- 목록 밖 물질은 PubChem 단일 명칭 매핑 후 조회 대상으로 추가합니다. CID 중복을 막으며, 문헌 물질의 과학적 식별 검토와 구별합니다.
- 고정 환경 문헌 검색의 최대 200개 원본 레코드에서 명칭 후보 제안 → 근거 문장 확인 → 조회란으로 가져오기.
  정규식 후보에는 비물질 문자열이 섞일 수 있습니다. 전체 화학물질을 찾거나 hot 여부를 판단한 결과가 아닙니다.
- 목록 갱신은 최대 12개 물질, 각 20페이지×100개 원본 레코드. 같은 범위의 당일 완전 자료를 우선 재사용하고 진행률·부분 실패를 표시합니다.
- 기본 탐색은 기존 자료만 읽습니다. 외부 호출은 추가·수집·후보 탐색 버튼으로 요청합니다.
- 기존 여섯 분석 탭은 상단 **물질 분석**에서 이용합니다. 세부 분석은 진입 시에 불러옵니다.

기본 조건(후반 최소 5건, 전반 최소 3건, 증가 3건, 증가율 50%)은 **잠정 운영값**입니다.
전반 0건의 증가율은 N/A이고 미수집·부분 수집·상세 날짜 미상은 증가 판정을 보류합니다.
선택 기간이 홀수 일수이면 가운데 하루는 증가 비교에서만 빼고 선그래프·문헌 목록에는 남깁니다.
전체 화학물질의 보편적 순위·위해성·연구 우선순위로 해석하지 않습니다.

## 구현한 사용자 흐름

1. **추이·문헌:** Europe PMC 수동 수집, 기간별 선그래프와 해당 논문 연결, 제목·초록 검색,
   매질·endpoint·모델 언급 필터, DOI/자료원 링크, 공개 원문 확보.
2. **맥락·근거:** 매질 × endpoint 공동 키워드 지도, 제목/초록/공개 원문 접근 수준, 절·문단·문자 위치,
   일치 단어, 부정·잠정·리뷰/배경·후속 연구 표현 표시. 실제 측정·영향 판정이 아닌 키워드 후보입니다.
3. **공백 검토:** 검출/노출·매질 언급을 출발점으로 제한된 후속 확인 질문을 생성하고,
   한계·근거 문헌·보완 검색식을 표시합니다. 보완 검색은 별도 저장하며 실제 완료 기록 없이 완료 처리하지 못합니다.
4. **물질 비교:** 공통 완결 연도의 endpoint 언급과 연결 논문 비교, 6PPD→6PPD-quinone 변환 관계
   언급·근거·불확실성 확인. 저장 문장을 직접 인용한 수동 관계 제안도 남길 수 있습니다.
5. **후보 검토함:** 저장 문헌에서 화학물질처럼 보이는 명칭을 최대 30개 제안 → PubChem 명칭 조회 →
   사용자 식별 검토·사유 → 관심 목록 편입. 같은 CID의 중복 물질 편입을 막고 자동 수집하지 않습니다.
6. **기준·기록:** 잠정 추세 조건/1년·2년 구간/완화·보수 조건 비교, 읽은 방법론 원문 3편의 근거표,
   검토 이력, JSON·CSV 내보내기, 실제 사용자 과업의 시간·대조 건수·효용 기록 도구.

## 기간 선택과 선그래프

추이·문헌 조회 기간에서 **5년간 / 1년간 / 1분기 간(최근 3개월)**을 선택합니다.
기준일까지의 달력상 최근 기간이며, 기본 집계는 각각 분기별 / 월별 / 주별입니다.
시작일·기준일·집계 단위도 직접 설정할 수 있습니다. 최초 기준일은 저장된 검색 범위의 최근 종료일입니다.

X축은 실제 출판 시점, Y축은 구간별 문헌 수인 선그래프입니다. 점을 클릭하거나 키보드 Enter/Space로 선택하면
해당 구간 문헌만 보입니다. 기존 +33건 단독 카드는 선택 기간·기간 내 건수로 바꿨습니다.
물질을 바꿔도 조회 기간을 유지하고 왼쪽 관심 물질 목록의 건수도 같은 기간으로 갱신합니다.

미수집 기간은 0건으로 연결하지 않습니다. 부분 수집·시작/종료일에 잘린 구간은 점선과 빈 점으로 표시합니다.
일자가 없는 문헌을 임의의 월·주로 배정하지 않습니다. 조회는 저장 자료만 사용하고 외부 요청·문헌/검토 기록 변경이 없습니다.
기간 선택은 추이·문헌 탭에 적용하며, 맥락·공백·물질 비교는 원본 스냅샷 기준이라는 점을 화면에 명시합니다.

추가 검사:

```sh
node tests/timeline-check.cjs
# 실제 로컬 서버가 8765에서 실행 중일 때, 읽기 전용 UI 검사
node tests/timeline-browser.cjs
```

검색 일치·PubChem 단일 매핑이 원문 물질·직접 실험을 확인했다는 뜻은 아닙니다.
Hot Radar는 선택 기간의 동일 일수 전·후반을 비교합니다. 기존 물질 분석의 endpoint 비교는 공통 완결 연도 2021~2025에 제한합니다.
분야별 전체 출판량·색인 지연·자료원 커버리지 차이는 보정하지 않습니다.

공개 원문 1편(간세포 연구)의 DOI·PMCID·CC BY 라이선스를 확인해 본문 26문단을 규칙으로 분석했습니다.
전 문헌의 원문을 읽거나 결과를 전문가가 검증한 것이 아닙니다. 보완 검색 1회 9건도 별도 저장했습니다.
실제 사용자 검토와 사용자 효용 평가는 **0건**입니다. 검사 기록은 복제 DB에만 있습니다.

CTD는 현재 네트워크 프록시에서 CONNECT 403으로 접근하지 못했습니다. 수동 조회 링크와 미수집 상태만
제공하며 CTD 유전자·질병 관계를 가져왔다고 주장하지 않습니다. PubChem 공식 조회는 정상 동작했습니다.

## 실행

Python 3.12+ 표준 라이브러리만 사용합니다. 앱 실행을 위한 패키지 설치·외부 AI·API 키가 필요 없습니다.
클라우드의 작업 디렉터리는 `/workspace/pioneer`입니다. 다른 컴퓨터에서는 압축을 푼 프로젝트 루트로 이동합니다.

```sh
cd /workspace/pioneer
python3 -m pioneer init
python3 -m pioneer doctor
python3 -m pioneer serve --port 8765
```

위 명령은 개발용 로컬 실행입니다. 공개 배포는 직접 포트를 여는 대신 `compose.yaml`과 HTTPS/인증 프록시 구성을 사용합니다. 운영 배포 절차는 `docs/deployment.md`를 따릅니다.
`init`은 기존 자료를 보존하며 스키마를 갱신합니다. 데이터는 `.data/pioneer.sqlite`에 있고 Git에서 제외됩니다.
**소스 ZIP에는 DB·수집 원문·백업이 포함되지 않습니다.** 현재 환경의 실제 자료를 보존하려면 DB 백업을 사용하세요.

## 수집·분석 명령

```sh
python3 -m pioneer collect 6ppd-q --start 2021 --end 2026 --max-pages 10
python3 -m pioneer identify 6ppd-q
python3 -m pioneer fulltext 6ppd-q MED:38922069
python3 -m pioneer discover
python3 -m pioneer export
```

`collect`, 캐시에 없는 `identify`, `fulltext`는 외부 요청과 DB 쓰기가 있습니다. `discover`는 기존 자료를 재사용합니다.
화면의 보완 검색도 외부 API를 호출합니다. 수집 기본 한도는 10페이지×100건, CLI `--max-pages`는 1–50입니다.
보완 검색은 최대 3페이지×100건입니다. 초과 결과는 partial입니다. 실패·부분 갱신이 이전 complete 스냅샷을
덮어쓰지 않으며 최근 시도와 표시 중인 스냅샷 차이를 알립니다. 자동 스케줄러·자동 무한 재시도는 없습니다.
429/일부 5xx만 짧게 최대 2회 재시도하며, 과도한 Retry-After는 조기에 재시도하지 않습니다. TLS 검증은 유지합니다.

자료원: `www.ebi.ac.uk`(Europe PMC), `pubchem.ncbi.nlm.nih.gov`(PubChem). `ctdbase.org` 접근은 현재 차단 관측 상태입니다.
유료 API 비용을 발생시키는 연동은 없으며 전체 실제 전송 횟수·비용은 정밀 계측하지 않았습니다.

## 백업·복원 검증

```sh
python3 -m pioneer backup .data/backups/my-snapshot.sqlite
python3 -m pioneer --db .data/backups/my-snapshot.sqlite doctor
python3 -m pioneer --db .data/backups/my-snapshot.sqlite serve --port 8768
```

새 경로를 지정해야 합니다. 기존 백업은 덮어쓰지 않습니다. SQLite backup API로 실행 중 DB도 일관되게 복사합니다.
복원 검증에는 원본을 덮어쓰지 말고 복사본을 별도 포트에서 여세요. 스키마 3의 무결성과 실행별 문헌 수를 검사합니다.

## 외부 호출 없는 합성 데모

```sh
python3 -m pioneer --db .data/demo.sqlite seed-demo
python3 -m pioneer --db .data/demo.sqlite serve --port 8766
```

데모는 실자료와 별도 DB이며 DOI·PMID·연구 성과를 꾸미지 않습니다. 외부 수집·원문 조회·식별·실자료 편입을 막습니다.

## 검사

```sh
python3 -m unittest discover -s tests -v
node --check web/app.js
node --check web/research.js
```

95개 단위·HTTP 통합 검사는 외부 호출 없이 임시 DB에서 실행합니다. 브라우저 검사에는 런타임에 준비된
Playwright와 `/usr/bin/chromium`을 사용합니다. 앱 실행에는 Node나 Playwright가 필요 없습니다.

실제 DB에 자동 검토 기록을 쓰지 않도록 검증용 복제본을 준비합니다. **기존 파일과 다른 새 경로를 지정하세요.**

```sh
python3 -m pioneer prepare-check .data/browser-check.sqlite
python3 -m pioneer --db .data/browser-check.sqlite serve --port 8767
# 별도 터미널, 같은 프로젝트 루트에서
node tests/browser-check.cjs
```

브라우저 스크립트는 `validation_copy` 표식이 없는 DB에는 검토·평가를 쓰지 않습니다. 현재 저장된 4개 물질,
공개 원문과 분석 결과를 재사용하고 자동 검사임을 명시한 기록을 복제본에만 씁니다. 19개 흐름과 모바일 6개 탭을
확인합니다. 캡처는 `.data/pioneer-context.png`, `.data/pioneer-mobile.png`에 저장됩니다.

## 과학적·운영 경계

- 후보 명칭 탐지는 제한된 문헌의 규칙 기반 제안입니다. 검증된 chemical NER·전체 환경문헌 신물질 발견이 아닙니다.
- 관심 목록·동의어·기간·추세 임계값·3건 이하 질문 생성은 잠정 운영 선택이며 검증된 hot 기준이 아닙니다.
- 지도는 문헌 내 공동 언급이며 실제 매질에서 측정한 endpoint 조합이라는 뜻이 아닙니다.
- 문헌 0건·키워드 미확인·미수집·부분 수집·분류 불가를 연구 부재·안전성·확정 공백으로 바꾸지 않습니다.
- DOI 또는 자료원 ID 중복은 제거하지만 서로 다른 DOI의 preprint/정식판·동일 자료 재분석을 완전히 판별하지 못합니다.
- 리뷰·정정·철회 관련 문서유형은 보이는 정보로 표시하며 철회 여부를 포괄적으로 검증하지 않습니다.
- 검색의 FIRST_PDATE와 집계의 firstPublicationDate를 우선합니다. pubYear 대체·연도 미상은 문헌별로 표시합니다.
- 문헌 제외 검토는 맥락 지도·질문에서 반영하지만 원본 검색 스냅샷·검색 건수·원본 차트를 삭제하지 않습니다.
- 사용자 검토자·평가자 이름은 직접 입력한 구분명이며 신원·전문성·판단의 독립 검증이 아닙니다.
- 자동 관계는 변환 언급, 수동 관계는 사용자 해석입니다. 구조 유사성 계산·독성 전이·CTD 추론을 수행했다고 표시하지 않습니다.
- 공개 원문은 API 접근 가능성뿐 아니라 라이선스·PMCID·DOI를 확인하고 처리하며 유료 원문 제한을 우회하지 않습니다.
- API 이용을 초록·원문 전체의 자유 재배포 허가로 간주하지 않습니다. 내보낸 근거도 출처와 이용 조건을 확인하세요.

## Hot Radar 검사

```sh
python3 -m unittest discover -s tests -v
node tests/timeline-check.cjs
node tests/timeline-browser.cjs
python3 -m pioneer prepare-check .data/radar-validation.sqlite
python3 -m pioneer --db .data/radar-validation.sqlite serve --port 8767
# 별도 터미널, 기존 Playwright/Chromium이 있는 검사 환경에서:
node tests/radar-browser.cjs
node tests/browser-check.cjs
```

브라우저 검사의 저장·검토·평가 입력은 validation_copy 표시가 있는 복제 DB에서만 수행합니다.
이 자동화 기록은 실제 사람 검토·성과 평가가 아닙니다. 앱 운영에 Playwright 설치는 필요하지 않습니다.
원 기획 대비 보완 범위·미완료 과학적 검토는 `docs/plan-gap-review.md`에 정리했습니다.
